# 开发规范

## 命名

- 类名和文件名使用 PascalCase，例如 `GameWorld.js`。
- 普通函数和变量使用 camelCase。
- 场景、资源、事件和状态的稳定键集中在常量或配置中。
- 中文注释和中文界面文本不进入代码标识符。

## 模块边界

- 跨项目数据结构只能来自 `platform_contract`，禁止在 dome 内复制 schema 或迁移规则。
- 场景不直接写战斗公式。
- UI 不直接修改玩家生命或背包。
- 配置仓库之外不直接读取 Phaser Cache。
- 高频逐帧数据不通过事件总线广播。
- 场景关闭时清理输入监听、事件监听和定时器。

## 数值配置

角色生命、攻击、防御、速度和技能参数必须进入 JSON。代码中的数字只用于纯视觉布局或通用引擎设置。

## 存档版本

修改存档结构时，应提升 `APP_CONFIG.saveVersion`，并为旧版本增加迁移逻辑。禁止悄悄改变已有字段含义。

## 验证命令

```powershell
npm run check
npm test
npm start
```
